# キーボード優先アプリ開発チェックリスト（Clicks Communicator 向け・コミュニティ版）

Clicks Communicator は「物理キーボード」と「1080×1200 のほぼ正方形の小さな画面」を持つ Android 端末です。
このチェックリストは、Android 標準の API だけで、この端末で気持ちよく使えるアプリにするための確認項目です。
Clicks 独自の API には依存しません（公開されていないため）。

> 非公式のコミュニティ資料です。実機での確認結果が出たら更新してください。

## 1. 画面サイズ

画面密度を 420dpi と仮定すると、表示領域はおよそ **411 × 457 dp** です（実機の値は `adb shell wm size` と `adb shell wm density` で確認）。
一般的な縦長スマホ（高さ 800dp 前後）の半分ほどの高さしかありません。

- [ ] 高さ 480dp 未満（WindowSizeClass の高さ Compact）でもレイアウトが破綻しない
- [ ] 主要な操作ボタンがスクロールしないと見えない位置に行っていない
- [ ] 固定ヘッダー、固定フッター、ボトムナビゲーションが画面の大半を占めていない
- [ ] ダイアログやボトムシートの中身がスクロールできる
- [ ] 文字サイズを大きくした設定（フォントスケール 1.3 以上）でも読める
- [ ] 向きを縦に固定している場合も、正方形に近い比率で表示が崩れない

## 2. 物理キーボードでの操作

物理キーボードが接続されている間、ソフトウェアキーボードは通常表示されません。

- [ ] すべての操作がタッチなしで到達できる（Tab / 矢印キーでフォーカス移動）
- [ ] フォーカスされている要素がはっきり見える（フォーカス表示を消していない）
- [ ] フォーカス順が見た目の順序と一致している
- [ ] 文字入力欄で Enter キーの挙動が自然（チャットなら送信、複数行なら改行など。Shift+Enter との使い分けも検討）
- [ ] Esc キーでダイアログや検索を閉じられる
- [ ] IME の「送信」ボタン（`imeOptions`）だけに頼った処理になっていない（物理キーボードではそのボタンが表示されない）
- [ ] キーボードの接続状態が変わってもアクティビティの状態が失われない（`keyboard` / `keyboardHidden` の構成変更）

実装のヒント:

- View: `onKeyDown` / `onKeyShortcut`、`android:nextFocusDown` など
- Compose: `Modifier.onKeyEvent` / `onPreviewKeyEvent`、`Modifier.focusable()`、`FocusRequester`

## 3. キーボードショートカット

- [ ] よく使う操作にショートカットを用意している（例: Ctrl+N 新規作成、Ctrl+F 検索、Ctrl+Enter 送信）
- [ ] ショートカットを `Activity.onProvideKeyboardShortcuts` で登録し、Android 標準のショートカット一覧（Meta+/）に表示されるようにしている
- [ ] 単独の文字キーをショートカットに使う場合、文字入力欄にフォーカスがあるときは発動しない
- [ ] システムが使うキーの組み合わせと衝突していない

## 4. Clicks 独自機能と相性をよくする（標準 API の範囲）

Message hub、Signal LED、Clicks Key が何を参照するかは公開されていません。
以下は Android 標準の作法で、こうした機能が情報を拾いやすくなると期待できるものです（実機で要確認）。

- [ ] メッセージ系アプリは `Notification.MessagingStyle` と `Person` を使い、会話通知として出している
- [ ] 会話ごとに長期ショートカット（`ShortcutManagerCompat.pushDynamicShortcut`）を公開し、通知に `setShortcutId` を設定している
- [ ] 通知チャンネルを用途ごとに分け、ユーザーが重要度を選べる
- [ ] 通知から返信できる（`RemoteInput`）
- [ ] 主要な機能を App Shortcuts（静的・動的）として公開し、ショートカットキーやランチャーから呼び出せる
- [ ] 外部から呼べる Intent（例: 新規メモ、録音開始）をドキュメント化している

## 5. 音声入力とアクセシビリティ

- [ ] 文字入力欄が音声入力（IME 経由の入力）でも正しく動く
- [ ] TalkBack とスイッチアクセスで主要な操作ができる
- [ ] タッチ領域が 48dp 以上ある（画面が小さくても詰め込みすぎない）

## 6. テスト方法

1. `avd/create-avd.sh` で Communicator 相当のエミュレーターを作る
2. エミュレーターでホスト PC のキーボードを使い、マウスを触らずに主要な画面を一通り操作する
3. 設定 > ユーザー補助 でフォントサイズを最大にして同じ確認をする
4. 実機が手に入ったら、キーボード面のスクロール操作や指紋センサー付きスペースキーとの干渉を確認する

## 未確認事項（実機で確認したいこと）

- 実際の画面密度と dp サイズ
- キーボード面のタッチ操作（スクロール）がアプリにどのイベントとして届くか
- Message hub と Signal LED が参照する通知の条件
- Clicks Key に割り当てられる対象（アプリ、App Shortcuts、Intent など）
